Database Query

Admin only (ADMIN_V1). Run supported SQL against the server database and see the outcome here. The box takes a whole script: every ;-separated statement is executed, one after the other, and the result lists what each one did. A successful DQL query (SELECT / VALUES) downloads its complete result as a CSV file — column names as the header row, every returned data row below. DML and DDL scripts commit together: if one statement fails, the whole script is rolled back and the failing statement is shown with its database error, so nothing is half-applied.

How it works

  • Pick the category first: it validates the statement you typed (a DELETE under DQL is rejected before it runs).
  • DQL (SELECT, VALUES) returns the complete result set as a CSV download with the column names on the first row.
  • DML (INSERT, UPDATE, DELETE, REPLACE), DDL (CREATE, DROP, ALTER, VACUUM) and TCL (BEGIN, COMMIT, ROLLBACK, SAVEPOINT) report success without a file.
  • Paste several statements at once — each one runs and its row count is listed below the status line, e.g. all the DELETE FROM ... where 1 = 1 statements of a cleanup script in a single execution.
  • Empty queries never run; a failing statement shows the actual database error on this screen, named with its position in the script, and a DML / DDL script is rolled back as a whole. Every execution is audit-logged with your user, the SQL and the outcome, with a statement timeout and a maximum result size in force.
